### 一、任务22「STM32 TIMER编码器测速」完成 ✅

**对应任务**：阶段三 任务22 STM32 TIMER编码器测速（读取电机编码器脉冲，实现测速，为后续闭环/PID 控制做准备）

- **任务目标**：在 STM32F103 上使用 **TIMER 编码器模式** 读取电机编码器脉冲，把**电机速度转换成编码器的值打印出来**，为「跑得好（左右轮转速一致）」的闭环控制打基础。

- **新建工程** `stm32/5_Timer编码器测速/`（复用任务21 的 4_PWM 工程）：
  - `USER/encoder.c` / `encoder.h`：**编码器初始化**——TIM2（左轮 PA0/PA1）、TIM3（右轮 PA6/PA7），编码器接口模式 `TIM_EncoderMode_TI12`（T1/T2 双沿计数，提高采样精度），预分频 0、ARR=65535、输入滤波、使能更新中断、清零后使能。
  - `USER/stm32f10x_it.c`：`SysTick_Handler` —— 1ms 中断计数，每 **20ms** 读一次 `TIM2->CNT`/`TIM3->CNT` 并置采样标志。
  - `USER/main.c`：编码器初始化 + 电机开环驱动（前进 2s → 停 → 后退 2s → 停）+ 每 20ms 采样测速，串口打印左右轮计数值 / 转速 / 线速度。

- **测速与线速度换算**：
  ```
  每秒脉冲数 = 20ms 内脉冲增量 × 50
  转速(圈/s) = 每秒脉冲数 ÷ 一圈脉冲数
  线速度(cm/s) = 转速(圈/s) × 轮子周长(cm)
  ```

- **关键标定（实测）**：
  - **一圈脉冲数 = 2800**（替代理论推算 1440，因各车编码器线数/减速比/倍频不同，以实测为准）
  - **轮子周长 = 14.25 cm**（用户提供，用于线速度换算）

- **编译成功**：Keil MDK5 编译 **0 Error / 0 Warning**，生成 `Template.axf` / `Template.hex`；`encoder.c` 已加入工程的 USER 源文件组。

- **实机验证** 🔥：
  - 踩坑①：Keil 下载器默认 ULINK2，需在 Options → Debug 切到 **ST-Link Debugger**，并在 Utilities 勾 `Use Debug Driver`。
  - 踩坑②：切到 ST-Link 后报 `No Algorithm found`，需在 Utilities → Settings → Programming Algorithm 添加 **`STM32F10x_128`**。
  - 踩坑③：**供电问题**——电机驱动(L9110S) 的 `M-5V` 只由电池经 LM2596 降压供给，与 USB 无关；所以**电机转 + 串口同时工作，必须电池供电（JP4 8.4V/2S）+ 串口走 USB（TypeC）二者并存**。插 USB 时空电池不接 → 电机不转；只电池无串口 → 电机转但 UartAssist 断联。解法：电池接 JP4 且同时插 USB。
  - 踩坑④：进 KEIL 配置 ST-Link 下载、添加 Flash 算法、确认供电后，**实机成功**——电机按「前进 2s → 停 → 后退 2s → 停」循环，串口每 20ms 打印左右轮 cnt / rev/s / cm/s。
  - 另外：两轮相同 PWM 会因左右轮实际转速不同而**走弧线**（开环本质），这正是后续闭环（任务23 PID）要用编码器反馈解决的问题。

## 收获总结

1. **掌握了 STM32 定时器编码器接口模式的原理与使用**：理解编码器把角位移/位移转成脉冲，用定时器输入捕获配置编码器接口（TI12 双沿计数）读脉冲，`CNT` 计数值即编码器角度信息。
2. **理解了重装载值 ARR 与预分频 PSC 在编码器测速中的含义**：分出外部时钟（编码器脉冲），`一圈脉冲 = 线数 × 倍频 / (PSC+1)`。
3. **学会了测速换算链路**：脉冲增量 → 每秒脉冲 → 转速(圈/s) → 线速度(×周长)；并认识到**一圈脉冲数必须实测标定**（我实测 2800），不能只用理论推算，这正是"每台车不一样、要自己调"的体现。
4. **摸清了小车供电结构**（查原理图）：电机 `M-5V` 走电池→LM2596，主控 `3.3VD` 走电池/USB 二极管隔离，二者独立——所以"电机转 + 串口看数据"需电池与 USB 并存供电。
5. **定位了"跑歪"的根因**：开环给相同 PWM，两侧实际转速不同 → 走弧线；这正是下一步闭环（PID）要解决的核心问题。
