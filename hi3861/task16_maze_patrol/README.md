# 迷宫巡逻（task16_maze_patrol / 14.0_Maze_Patrol）：避障 + 防跌落二合一

**任务24 桌面巡逻版的迷宫演示强化**：小车在纸箱围成的迷宫里自主巡逻 **2 分钟**——
超声波避障不撞箱子；TCRT5000 红外朝下检测**黑色胶带禁区**（不能碰到也不能进去），
同一套检测同时覆盖**桌沿防跌落**（黑胶带吸红外与"下方无反射"对 TCRT 是同构信号）。

```
                        ┌─ TCRT5000 左 GPIO_13 / 右 GPIO_14（朝下）
 HC-SR04(GPIO7/8) ←──────┤
    ↑装在 SG90(GPIO_2) 云台，可左右扫 45° 选路
                        └─ 危险读数 → 停 → 倒车 300ms → 朝另一侧转 90°
STM32 侧不变：任务24 双核 V2 协议（9600 版，无需重烧）
Hi3861 → GPIO11 软件 UART TX @9600 → STM32 PA10（task15 实机验证的传输层）
```

## 与 task14（桌面巡逻）的差异

| 项 | task14 桌面巡逻 | task16 迷宫巡逻 |
|---|---|---|
| 传输层 | 硬件 UART2 @115200 | **GPIO11 软件 UART @9600**（实车 STM32 已是 9600 版，免重烧） |
| 防跌落 | `EDGE_GUARD_ENABLE=0`（地面测试时关闭） | **启用**，且防跌落与黑胶带禁区共用一套检测 |
| 计时 | `usleep` 循环次数近似 | **全部 `hi_get_us()` 实时时间**（软 UART 每帧 10.4ms，循环计数不可靠） |
| 转向后脱离 | 盲直行 2s（500ms 后被 STM32 看门狗停住） | **受控直行 700ms**，中途踩线/遇箱立即处理 |
| 演示时限 | 无 | **上电标定 2s + 倒计时 3s + 巡逻 120s 自动停** |

## 核心机制

1. **开机标定（关键）**：车静止摆在**迷宫通道的普通地面**上（别压胶带、别在深色地面上），
   上电后 2s 内每 50ms 采样一次左右红外、每侧多数表决出"地面电平"；读数不稳定时串口
   打印 `(UNSTABLE? check position!)` 提示重新摆位。之后 `读数 != 地面电平` 即危险。
2. **危险 = 桌沿 = 黑胶带**：TCRT5000 朝下，正常地面有红外反射；桌沿（无反射）和
   黑胶带（吸收红外）都让读数偏离地面电平。触发即：停 → 倒车 300ms 脱离 → 朝另一
   侧转 90° 远离边线。检测带 3ms 二次确认滤瞬时噪声。
3. **超声波避障（task14 实机标定逻辑）**：前方 <20cm → 停 → 舵机左/右扫 45° 各测
   3 次取中值 → 向空侧单轮支点转 90°（1400ms 实测）；双侧都堵 → 掉头 180°。
   测距带 30ms 超时保护（回波丢失返回 999=无障碍，不会挂死）。
4. **全程心跳供帧**：STM32 有 500ms 无有效帧自动停车保护。测距 ≤30ms 天然安全；
   舵机扫描期间每帧持压都同步发一帧 `stm32_send_frame(0,0)` 维持心跳。
5. **受控运动段**：前进/转向/脱离每 40ms 查一次红外（8.5cm/s 速度下每查走 ~3.4mm），
   任何动作中途踩到胶带立即停 → 倒车改道，绝不盲跑。

## 参数速查（`maze_patrol.c` 头部集中定义）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `DEMO_RUN_SECS` | 120 | 演示总时长，到点自动停车 |
| `CRUISE` | 60 | 巡航速度 0.6 圈/s ≈ 8.5cm/s（留足检测余量，勿快于 80） |
| `OBSTACLE_CM` | 20.0 | 前方障碍阈值（cm） |
| `TURN_90_MS` | 1400 | 单轮支点转 90° 实测时长，跑偏就微调 |
| `BACK_MS` | 300 | 红外触发后倒车脱离时长 |
| `ESCAPE_MS` | 700 | 转向后受控直行脱离时长 |

> 舵机标定沿用 task14：`SERVO_CENTER_US 1650`（回中）、`SERVO_LEFT_US 2200`（左 45°）、
> `SERVO_RIGHT_US 1100`（右 45°）。

## 演示步骤（U+ 演示脚本）

1. **确认 STM32 是 9600 版任务24 固件**：上电车灯状态正常（停车=后红前灭）、
   若是别的协议需重烧 `stm32/8_双核协议控制`（`main.c` 里 `uart_init(9600)`）
2. 串口开关拨 3861 端接好（看日志），小车**电池供电**（USB 带不动电机）
3. 小车摆进迷宫通道的普通地面上（**别压黑胶带**），上电
4. 等串口 `Ground: L=x R=y OK` + `Start in 3s` 倒计时，期间人离场
5. 小车自主巡逻 2 分钟：避箱、避胶带；到时打印 `DEMO DONE, car stopped.` 自停

## 实机验证清单（联调顺延，待做）

按顺序验证，每步都有明确的观察点：

| # | 步骤 | 预期观察 |
|---|---|---|
| 1 | 摆车（普通地面，别压胶带）上电，看串口 | `Ground: L=x R=y OK`（若打 `UNSTABLE?` → 车摆位置反射不稳定，换位置重上电） |
| 2 | 倒计时 3s 内不动车 | 到点才起步，起步前车完全静止 |
| 3 | 手掌挡车前 15cm → 车接近到 ~20cm 应停 | 串口 `OBSTACLE xxcm` → `SCAN L=xx R=xx` → `TURN LEFT/RIGHT 90`，转向灯随动 |
| 4 | 黑胶带平铺车前方地面 | 车头压线前停：`DANGER LEFT/RIGHT -> back+turn`，倒车+转向后绕开，不碾胶带 |
| 5 | 双侧堵死（两手掌夹车前） | `BOTH BLOCKED -> U-TURN` 180° 掉头 |
| 6 | 计时跑迷宫 2 分钟 | 不撞箱、不进胶带区；`DEMO DONE, car stopped.` 自停 |

微调指引（先看现象再动手，一次只调一个）：

- **对胶带反应太晚（前轮已压线）**：`CRUISE` 60→50，或确认胶带宽度 ≥5cm、
  与地面颜色对比强（浅色地面最佳）
- **对箱子快撞上才转**：纸箱吸音回波弱，`OBSTACLE_CM` 20→25
- **转向角度不准**：`TURN_90_MS` ±100ms 逐步调（低速 0.6圈/s 时 1400ms≈90°）
- **迷宫通道窄、转向后直行又撞**：`ESCAPE_MS` 700→400
- **想改演示时长**：`DEMO_RUN_SECS`（120=2 分钟）

**恢复旧固件**：演示后想回到蓝牙遥控，重烧
`task15_ble_control/output/Hi3861_wifiiot_app_allinone.bin`（md5 `ec616dcc…`）即可，
STM32 侧无需任何改动（同为 9600 V2 帧）。

## 常见问题

- **标定打印 UNSTABLE**：车压在胶带上/地面对比度不够/桌面过黑。挪到普通地面重新上电。
- **老是压胶带才停**：车速过快或胶带太窄。确认 `CRUISE=60`；再把黑胶带贴宽些
  （**至少 5cm 宽**，演示场地已确认满足）并与地面颜色对比明显。
- **对箱子快撞上才转**：纸箱吸音/表面倾斜回波弱。可把 `OBSTACLE_CM` 调大到 25。
- **转向不足/过度反复撞同一箱角**：实测微调 `TURN_90_MS`（±100ms 一步）。
- **走走停停**：典型供帧断流——确认固件是本工程（舵机扫描期间持续供帧）而非 task14 老版。
