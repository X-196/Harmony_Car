# 蓝牙遥控小车（task15_ble_control / 13.0_BLE_Control）

**扩展应用**（U+ 平台无对应任务，自创综合）：把**任务9 的蓝牙透传**（UART1 + JDY-16）接到**任务24 的双核运动协议**（UART2 → STM32）上，手机蓝牙 App 单字符命令遥控小车。

> 命令设计沿用手机九宫格：`W/A/S/D` 方向、`O` 停止（圆心）、`I/K` 两档速度。兼容大小写；回车/换行/空格忽略（适配蓝牙调试器的"发送新行"选项）。

## 链路

```
手机蓝牙App ──BLE──> JDY-16 ──UART1 (GPIO_0=TX/GPIO_1=RX, 9600)──> Hi3861
                                                               case 分发
Hi3861 ──UART2 (GPIO_11=TX/GPIO_12=RX, 115200)──> STM32 (stm32/8_双核协议控制)
        V2 10字节帧: FC|02|0A|左轮int16LE|右轮int16LE|seq|XOR|FD
STM32: PID 闭环驱动电机 + 按帧渲染转向灯/倒车灯
```

## 命令表

| 字符 | 动作 | 帧内容（左轮,右轮 ×0.01圈/s） |
|---|---|---|
| `W` | 前进 | (speed, speed) |
| `S` | 后退 | (-speed, -speed) |
| `A` | 左转（左轮停/右轮转，支点转向） | (0, speed+15) |
| `D` | 右转 | (speed+15, 0) |
| `O` | 停止 | (0, 0) |
| `I` | 速度档 100（默认） | 只改档位不发帧 |
| `K` | 速度档 150 | 只改档位不发帧，下次 W/S 生效 |

备用字母（App 按钮键盘只有 A~K 时映射用）：`B`=后退、`C`=右转、`E`=停止、`F`=左转。

## 可靠性设计

STM32 侧（任务24 固件，**无需重烧**）有 **500ms 无有效帧自动停车**的失效保护，遥控模式必须持续供帧：

1. **心跳重发**：`ble_ctrl_task` 在同一个任务里每 100ms 重发当前目标帧，保证 STM32 始终有有效帧
2. **命令即发**：收到命令立即发一帧，不等心跳周期
3. **单线程发送**：蓝牙接收和 UART2 心跳由同一个任务完成，不再由两个任务并发调用 `UartWrite`，避免调度/并发导致控制帧时序异常
4. 串口 0 printf（命令回显）与 UART2 控制帧分走两个串口，互不干扰
5. **初始化顺序**：必须先初始化 UART2（STM32，115200），再初始化 UART1（蓝牙，9600）。隔离测试证明旧版 Hi3861 UART HAL 在反向顺序时会导致 UART2 不出有效波形。

> 走停由手机 App 控制：按下方向键发动作（按住期间心跳维持），松开发 `O`（或按停）停车。

## 手机蓝牙调试器按键设置（实测：xnj.lazydog 蓝牙调试器）

该 App 按钮键盘**可以自定义每个按键**：按钮界面右下角**编辑模式** → 点任意按钮 → 填**显示名称 / 按下发送 / 松开发送**三项 → 结束编辑。每键支持按下/松开各发一条数据。

- 每键支持**按下发送 / 松开发送**两条独立数据。
- ⚠️ **关键坑（实测踩过）**：若"前/后/左/右"的**松开发送设为 `O`**，则**每次点按都会"发动作→立刻发停止"**，车来不及起步，看着像没反应。两个方案：
  - **方案 A · 按住走松手停**：把方向键"松开发送"留空，然后**长按**方向键不松手，车持续走（心跳维持供帧），松手即停；停止用独立按钮 `O`。
  - **方案 B · 点一下走 2 秒**：同样把"松开发送"留空，单独一个"停"按钮映射 `O`；点一下 `W` → 车走 2 秒后自动停（固件 2s 无命令自动停）。

推荐映射（方案 A，按住走松手停）：

| 按钮显示 | 按下发送 | 松开发送 |
|---|---|---|
| 前 | `W` | 空 |
| 后 | `S`（或 `B`） | 空 |
| 左 | `A`（或 `F`） | 空 |
| 右 | `D`（或 `C`） | 空 |
| 停 | `O`（或 `E`） | 空 |
| 慢 | `I` | 空 |
| 快 | `K` | 空 |

> 方向键**松开发送务必留空**——否则松手立刻停，车动不起来（这是"按了没反应"最常见原因）。

> 松手停是体验最好的方案：车不会因为你忘记按停而一直跑。若只想点按控制，松开发送留空即可。

## 编译与烧录

1. 上传 `13.0_BLE_Control/` 到虚拟机 `applications/sample/wifi-iot/app/`，改 app/BUILD.gn 指向 `13.0_BLE_Control:ble_control`（见 `reference/app_BUILD.gn`）
2. `python3 build.py wifiiot` → 产物拷回 `output/Hi3861_wifiiot_app_allinone.bin`（最新顺序修复版 md5 `166ad037e41801a974bc9f12e8262338`）
3. HiBurn：COM 选 CH340（COM9）、波特率 2000000、选 allinone.bin、勾 Auto burn → Connect → 按复位键；烧完取消 Auto burn
4. **STM32 侧不用重烧**：沿用 `stm32/8_双核协议控制/` 固件（V2 帧解析 + PID + 车灯）

## 联调步骤（实测要点）

1. 小车**电池供电**（USB 只够芯片+灯带，电机不动——见记忆/实测）；串口开关拨到 3861 端烧录
2. 烧完拨回运行，手机装 `tools/_bt_debug/蓝牙调试器xnj.lazydog.btcontroller.apk`
3. 搜蓝牙设备：**认实际广播名**（本车模块改名过，如 `Gamer_0o0`，不叫 JDY-16）
4. 连接后进"键盘/按钮"模式，把按键映射成单字符：`W/A/S/D/O/I/K`
5. 串口日志（115200）应看到 `BLE control ready: W/A/S/D/O + I/K`，每按一键打印 `CMD W: forward 100` 等
6. 按 `W` 走直线、`A/D` 原地转（转向灯闪）、`S` 倒车（倒车灯）、`O` 刹停（刹车灯）、`K` 后再 `W` 明显变快

## 常见问题

- **按键后车不动**：看串口有无 `CMD W: forward 100`。有 `CMD` 说明命令已解析、帧已发出，但车不动——先查电池电压（USB 只够灯带），再看 STM32 是否收到有效帧（若帧被并发破坏会校验失败丢弃，已用局部缓冲+互斥锁修复）。连 `CMD` 都没有则蓝牙没连上/波特率不对（UART1 固定 9600）
- **走两步自己停**：命令超时自动停是 2s——按住方向键或让 App 持续发即可；正常情况按运动命令车就走，松手 2s 后自动停
- **灯不闪/灯乱**：与任务24 相同的灯带标定问题，见 `stm32/8_双核协议控制/README.md`
