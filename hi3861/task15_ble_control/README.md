# 蓝牙遥控小车（task15_ble_control / 13.0_BLE_Control）

**当前架构（9600 间歇分时版）**：本车 Hi3861 旧版 UART HAL 在 UART1（蓝牙）与 UART2（STM32）同时启用时会导致 UART2 失效，因此彻底不调用 `UartInit(UART2)`：

- UART1 硬件串口：GPIO0/1，9600，接蓝牙模块（JDY-16）
- GPIO11 软件 UART TX（**9600**）：仍使用板上已经焊死的 `GPIO11 → STM32 PA10/RX` 线路，只改变 Hi3861 内部驱动方式，不改硬件
- GPIO12 焊线保持原样即可；本程序不读取 STM32 回传，不需要拆线
- **间歇式单任务** `ble_ctrl_task`：平时轮询蓝牙命令，收到命令或到 100ms 心跳点才发一帧，发完立刻继续听蓝牙——发送与接收不并发，互不抢占

> 9-02 实测：115200 位倒（9us/位）在 RTOS 中断+任务调度下字节被拉宽，STM32 一帧都解不出来。改 9600（104us/位）后位倒误差和中断抖动都可忽略。**代价：STM32 侧要同步改成 9600 并重烧**（`stm32/8_双核协议控制/USER/main.c` 的 `uart_init(9600)`）。

> 命令格式：**方向字母 + 可选数字（单位 0.1s）**，例如 `w50` = 前进 5 秒后自动停车；不带数字 = 持续到 `o` 停车。JDY-16 的 `+CONNECTED`/`+DISCONNECTED` 状态行整行吞掉，断连自动停车，不再误触发按键。

```
手机蓝牙App ──BLE──> JDY-16 ──UART1 (GPIO_0=TX/GPIO_1=RX, 9600)──> Hi3861
                                                               分时轮询/发帧
Hi3861 ──GPIO11 软件UART TX, 9600──> STM32 PA10 (stm32/8_双核协议控制)
        V2 10字节帧: FC|02|0A|左轮int16LE|右轮int16LE|seq|XOR|FD
STM32: PID 闭环驱动电机 + 按帧渲染转向灯/倒车灯
```

| 链路 | 连接 |
|---|---|
| 蓝牙模块 TX | Hi3861 GPIO_1（UART1_RXD） |
| 蓝牙模块 RX | Hi3861 GPIO_0（UART1_TXD） |
| Hi3861 GPIO_11（软件 UART TX） | STM32 PA10（USART1_RX） |
| Hi3861 GND | STM32 GND |

## 命令表

格式：**小写方向字母 + 可选数字**（数字单位 0.1s，最长 600 即 60s 封顶）。数字结束的判定：遇到非数字字符，或 100ms 内没有新字节——App 整串发送即可，无需回车结尾；如果 App 会自动补回车，收尾更快。

| 输入 | 动作 | 说明 |
|---|---|---|
| `w50` | 前进 5s 后自动停车 | (speed, speed)，0.1s×50 |
| `s30` | 后退 3s | (-speed, -speed) |
| `a15` / `d15` | 左/右转 1.5s | (0, speed+15) / (speed+15, 0) |
| `w` `s` `a` `d` | 不带数字：持续运行 | 直到 `o` 停车（兼容旧玩法） |
| `o` | 立即停车 | 同时取消正在倒计时的定时命令 |
| `i` / `k` | 速度档 100（默认）/ 150 | 只改档位，下一次运动生效 |
| `w0` | 立刻停 | 数字为 0 等价于停止 |

备用字母（App 按钮键盘只有 A~K 时映射用）：`b`=后退、`c`=右转、`e`=停止、`f`=左转，同样可跟数字。大写字母也兼容。

运行中收到新命令会直接覆盖：比如 `w50` 还没跑完又发 `d20`，立即改为右转 2s。

## 可靠性设计

STM32 侧（任务24 固件）有 **500ms 无有效帧自动停车**的失效保护，遥控模式必须持续供帧：

1. **心跳供帧**：`ble_ctrl_task` 每 100ms 重发当前目标帧，保证 STM32 始终有有效帧；这个 0.1s 节拍同时兼作定时命令的倒计时
2. **命令即发**：命令收尾（数字超时判定）后立即补发一帧，不等心跳周期
3. **间歇分时**：蓝牙轮询（10ms）与发帧（约 10ms）在同一个任务里交替，不存在并发；发帧期间到达的蓝牙字节由 UART1 硬件 FIFO 暂存，发完再读
4. **9600 容错**：位宽 104us，`hi_udelay` 的 us 级误差和短中断拉长都不影响 STM32 采样
5. **断连保护**：JDY-16 断连时吐的 `+DISCONNECTED` 被识别后强制目标归零并立即发停车帧；串口日志可看到 `BLE CONNECTED` / `BLE DISCONNECTED` 事件
6. 串口 0 printf（命令回显）与 GPIO11 控制帧分走两个通道，互不干扰

## 手机蓝牙调试器按键设置（实测：xnj.lazydog 蓝牙调试器）

该 App 按钮键盘**可以自定义每个按键**：按钮界面右下角**编辑模式** → 点任意按钮 → 填**显示名称 / 按下发送 / 松开发送**三项 → 结束编辑。每键支持按下/松开各发一条数据。

- 现在命令自带时长，**松开发送全部留空**即可。
- 推荐映射（时长自己定，下面是例子）：

| 按钮显示 | 按下发送 | 效果 |
|---|---|---|
| 前5s | `w50` | 前进 5 秒自动停 |
| 后3s | `s30` | 后退 3 秒自动停 |
| 左1.5s | `a15` | 左转 1.5 秒自动停 |
| 右1.5s | `d15` | 右转 1.5 秒自动停 |
| 前（持续） | `w` | 一直前进，直到按停 |
| 停 | `o` | 立即停车 |
| 慢 / 快 | `i` / `k` | 速度档 100 / 150 |

> 也可以在 App 的文本发送框里直接输入 `w50` 这类字符串发送。

## 编译与烧录

1. 上传 `13.0_BLE_Control/` 到虚拟机 `applications/sample/wifi-iot/app/`，改 app/BUILD.gn 指向 `13.0_BLE_Control:ble_control`（见 `reference/app_BUILD.gn`）
2. `python3 build.py wifiiot` → 产物拷回 `output/Hi3861_wifiiot_app_allinone.bin`（v3 心跳探针版 md5 `ec616dcc8b82454d0af31095bfc8ed3d`）
3. HiBurn：COM 选 CH340（COM9）、波特率 2000000、选 allinone.bin、勾 Auto burn → Connect → 按复位键；烧完取消 Auto burn
4. **STM32 侧必须重烧（9600 版）**：Keil 打开 `stm32/8_双核协议控制/USER/Template.uvprojx` 编译 → ST-Link 下载。`main.c` 已改为 `uart_init(9600)`，此后 STM32 调试串口（PA9）也是 9600

## 联调步骤（实测要点）

1. 小车**电池供电**（USB 只够芯片+灯带，电机不动）；确认 STM32 烧的是 9600 版任务24固件；串口开关拨到 3861 端烧录
2. 烧完拨回运行，手机连接实际蓝牙广播名
3. 按上面映射配好 App 按键
4. 串口日志应看到 `BLE control ready: w/s/a/d+time(0.1s), o stop, i/k speed`；手机连上/断开会打印 `BLE CONNECTED` / `BLE DISCONNECTED: auto stop`
5. 发 `w50`：日志打印 `CMD w: 50 x0.1s (L=100 R=100)`，车前进 5s 后打印 `AUTO STOP` 自动停车；观察车灯：前进时前白后暗红

## 常见问题

- **按键后车不动**：看串口有无 `CMD w: ...` 回显。有回显说明命令已解析、帧已发出，但车不动——先查电池电压（USB 只够灯带），再发 `w` 看车灯：前白后暗红=帧已到 STM32，查电机供电/接线；灯不变=帧没到，用 CH340 接 GPIO11（9600 8N1 HEX 显示）应看到持续 `FC 02 0A ... FD` 帧流
- **发了 `w50` 约 0.1s 后才有反应**：正常——数字收尾靠 100ms 无字节超时判定（不知道后面还有几位数）。想零延迟，让 App 发送时结尾加回车
- **走一步就停（曾踩坑）**：本内核 tick=100Hz（1 tick=10ms），曾误把 `osDelay(10)` 当 10ms 用，实际循环一圈 100ms、心跳被放大到 1s+，超过 STM32 500ms 失效保护。现版心跳/倒计时全部用 `hi_get_us()` 真实时间；若仍出现，查 GPIO11 连线和共地
- **连上蓝牙车自己动了一下**：旧版把 JDY-16 的 `+CONNECTED` 状态串误解析成按键（结尾 `D`=右转）。现版已整行吞掉状态串，不会再出现
- **灯不闪/灯乱**：与任务24 相同的灯带标定问题，见 `stm32/8_双核协议控制/README.md`
