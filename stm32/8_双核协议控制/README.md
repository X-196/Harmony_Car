# 任务24：8_双核协议控制（Hi3861 ⇄ STM32 双核综合）

把 Hi3861（主核）与 STM32（从核）综合起来：**Hi3861 发协议帧指挥小车自己跑，STM32 解析帧并闭环驱动电机，同时左转打左转向灯、右转打右转向灯、后退亮倒车灯**。

## V2 通信协议（当前版本）

为避免方向字段错位、帧损坏后误解析，当前使用 10 字节帧：

```text
FC | 02 | 0A | 左轮低字节 | 左轮高字节 | 右轮低字节 | 右轮高字节 | 序号 | XOR | FD
```

左右轮速度是有符号 `int16`，单位为实际转速的百分之一：`60` 表示 `+0.60` 圈/s，`-50` 表示 `-0.50` 圈/s。`XOR` 是 Byte1~Byte7 的异或校验。STM32 只接受版本、长度、帧尾和校验均正确的帧；连续 500ms 没有收到有效帧会自动停车。

当前避障逻辑：前进 → 前方小于 20cm 停车 → 舵机带超声波扫描左右各 3 次取中值 → 单侧畅通向该侧转 90°，两侧都畅通选更远侧，两侧都堵掉头 → 继续前进。


| 字段 | Byte | 值 | 功能 |
|---|---|---|---|
| 帧头 | 1 | `0xFC` | 判断数据帧头部 |
| 左轮方向 | 2 | 0 / 1 | 0 正转（前进）、1 反转（后退） |
| 左轮速度 | 3 | 0~150 | 精度 0.01，单位 圈/s（实际转速 ×100） |
| 右轮方向 | 4 | 0 / 1 | 同上 |
| 右轮速度 | 5 | 0~150 | 同上 |
| 帧尾 | 6 | `0xFD` | 判断数据帧尾部 |

## 两侧实现

### Hi3861（`hi3861/task14_uart_correspondence/12.0_UART_Correspondence/`）

- `stm32motor_control(motorA, motorB)`：讲解版协议打包函数——取绝对值拆方向、限幅 ±150、装 6 字节帧、`UartWrite(UART2)` 发出
- 动作函数：`car_forward(100,100)` / `car_backward(-100,-100)` / `car_left(50,150)` / `car_right(150,50)` / `car_stop(0,0)`
- **学生任务**（验证前进/后退/左转/右转）：`car_demo` 任务循环 **前进 2s → 左转 2s → 右转 2s → 后退 2s → 停止 2s**，串口 0 同步打印当前动作（`FORWARD/LEFT/RIGHT/BACKWARD/STOP`）
- 帧只在动作开始时发一次，STM32 锁存目标并持续闭环——避免 3861 连续发帧与串口打印互相干扰
- 固件：`output/Hi3861_wifiiot_app_allinone.bin`（HiBurn 烧录）

### STM32（本工程，`USER/Template.uvprojx`）

1. **帧解析**（`SYSTEM/usart/usart.c` `USART1_IRQHandler`）：讲解版逐字节状态机——非 `0xFC` 不计数（重新找帧头），收满 6 字节且第 6 字节为 `0xFD` → 提取 `CAR_buff[4]`（左方向/左速度/右方向/右速度），置 `uart_rec_flag`
2. **闭环控制**（`USER/pid.c` `System_Control`，SysTick 每 100ms）：收到帧 → 速度 `/100.0f` 还原 + 方向字节恢复符号 → 更新车灯状态 → 读两轮编码器 → `Rs_To_CPR` 目标换算 → 增量式 PI（Kp=7.0/Kd=0.003）→ `Set_Pwm`；复用任务23 调好的 PID 参数，走直线能力保留
3. **转向灯/车灯渲染**（`USER/main.c` `led_task`，主循环每 10ms）：按 `Car_Led_State` 渲染两条 WS2812 灯带（**前后各一条，每条 6 珠，实机验证**）：

| 运动状态（由协议帧判定） | 车灯效果 |
|---|---|
| 两轮同速正转（前进） | 前灯带白（大灯）+ 后灯带暗红（尾灯） |
| 右轮快于左轮（**左转**） | **前后灯带左半边各 3 珠闪琥珀色（350ms 半周期），右半边灭** |
| 左轮快于右轮（**右转**） | **前后灯带右半边各 3 珠闪琥珀色，左半边灭** |
| 两轮都反转（后退） | 倒车灯：后灯带红边白芯，前灯灭 |
| 两轮全零（停止） | 灯全灭 |

- 灯带映射（实机标定）：PC13（DIL）→**前灯带**，PC14（DIR）→**后灯带**；每条带的"左半边"由 `FRONT_STRIP_LEFT_IS_LOW` / `REAR_STRIP_LEFT_IS_LOW` 宏定义（实车标定为 4~6 号灯即两个宏均为 0，若换车/重装灯带重标定：单独翻转对应宏）
- 灯效全部在主循环分片渲染（每 10ms 一帧、WS2812 刷新 66µs 级），不阻塞电机闭环中断

## 实机验证（2026-09-01）✅

- 双核链路验证通过：3861 发帧 → STM32 解析 → 电机 PID 闭环驱动，小车循环 **前进 → 左转 → 右转 → 后退 → 停止**，转向灯/倒车灯/大灯尾灯按节拍正确切换
- **踩坑①（电机嗡嗡不转）**：轮子不转时编码器反馈为 0，PID 短时间把 PWM 推满仍带不动 → 电池电压不足，充电后恢复正常（USB 供电只能验证灯效，电机必须电池供电）
- **踩坑②（转向灯看似两边都亮）**：灯带实为**前后各一条**而非左右各一条，按左右布局渲染时"左转"点亮的是整条前灯带（横跨车头两角）→ 改为前后带各取对应侧半边闪烁
- **踩坑③（左右反了）**：前后两条带安装方向与假设相反，`FRONT/REAR_STRIP_LEFT_IS_LOW` 两个宏 1→0 翻转后修正（最终：左半边=4~6 号灯）

## 踩坑与设计决策

- **3861 连续发帧 vs 单次发帧**：讲解 demo 每 1s 在互斥锁下重发同一目标；本工程改为动作开始时发一次、STM32 锁存，行为等价且避免帧与 3861 串口日志在同口的冲突（3861 的调试 printf 走串口 0，与 UART2 分开，互不影响）
- **帧同步**：中断里 `USART_RX_BUF[0]!=0xFC` 即清零计数，流中任何垃圾字节都会被当作"未开始"丢弃，天然抗噪；帧尾只认第 6 字节 `0xFD`，错位 1 字节的帧会被下一次帧头重新同步
- **转向判定放 STM32 不放 3861**：协议帧只有轮速，方向语义（左转/右转/直行/倒车）由从核根据两轮带符号转速推断，主核协议保持讲解原样不动——以后 3861 换循迹/避障逻辑（`car_left_tra` 等），转向灯自动跟随，无需改协议
- `System_Control` 里 `CAR_buff` 消费后 `memset` 清零，防止旧帧重复消费
